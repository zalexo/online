How the prototype handles a display change

A reported cable reconnect problem motivated this project. The code learns local layouts and attempts restoration; real hotplug, fullscreen Space identity and focus preservation remain unverified.

Transition Gate

A display callback advances a lock-protected epoch. Capture admission blocks learning during transitions and self-generated restore operations; isolated tests check profile preservation.

Live AX Registry

The runtime uses live Accessibility elements and cached handles. A separate read-only Spaces summary shows fullscreen and display records, which may overlap AX or be stale. It is not a complete inventory of windows on unseen Spaces.

Cross-Relaunch Rebind

Existing-window matching can use a unique boot, process-launch and system-window reference. Fallback requires a meaningful accessibility ID, compatible mode and agreeing geometry. Ambiguous candidates are withheld; durable identity is not guaranteed.

Lazy Space Catch-Up

Pending windows are reconsidered after user Space or application changes. The configured 0.35s delay is not a measured response guarantee, and inaccessible windows may remain pending.

Experimental fullscreen conversion

The Engine can request exit, move and re-entry, or leave a window maximized. A final mode/display readback is required before success. This path can run automatically; same-Space continuity, Split View and focus are not verified.

Conservative window matching

The live registry uses process launch identity and AX element equality. Across relaunch, all matching signals must agree. Equal geometry, recency or enumeration order alone never select an identity.

Three queues, one local app

Swift and AppKit, without third-party packages or private WindowServer APIs. Serial AX and file queues separate window IPC from storage; end-to-end latency is not measured.

Three-Queue Isolation SIP Intact

Window IPC and disk work have separate queues

AX IPC runs on one serial queue with a 0.25s timeout per message. Profile IO, trace delivery and ZIP creation use the existing serial file queue. A per-message timeout is not a total scan budget or a responsiveness guarantee.

Main Thread (.main) AppKit menu, NSScreen snapshots, Space/App notifications (zero AX IPC)
app.windowharbor.accessibility Serial AX IPC queue + live AXUIElement cache (0.25s timeout)
app.windowharbor.profile Serial disk queue: atomic profiles.json, .backup, 2 MB trace.log
Local Data, Explicit Privacy

Local diagnostics contain identifiers

The AX adapter does not request title/document attributes or screenshots. Profiles retain opaque AXIdentifier values. Diagnostic ZIPs retain app/display identifiers, are not anonymous and are never uploaded automatically. 

~/Library/Application Support/WindowHarbor/
├── profiles.json         # mode 0600 (atomic write)
├── profiles.json.backup  # previous file
├── trace.log             # 2 MB ring log (no titles/URLs)
└── WindowHarbor-diagnostics-*.zip
Protected Local Storage

Atomic backups & one-click diagnostics

Save backs up the previous profile before atomic replacement. Read failure blocks learning; explicit recovery validates the backup and preserves the original. Diagnostic ZIPs explain their contents. A system logging profile is neither required nor bundled.

No Startup Jumps

Calm startup adoption, delayed verification, and Undo

The first trusted settle adopts the current setup without restoring. Ordinary geometry gets delayed verification; Undo Last Geometry Restore restores windowed frames and holds them from automatic learning. Fullscreen and Space Undo are unsupported.

Implemented code and unverified behavior

Core and isolated Engine tests cover selected safety paths. They do not establish real AX, display or application compatibility. See the repository verification journal for dated results.

Implemented in the source prototype

Isolated Checks

Local geometry profiles

Stores eligible window placements for exact display environments. Accessible cached handles can remain usable across Space changes. No complete Space inventory is implemented.

Relaunch matching with explicit refusal

The live registry can recover an existing window using a scoped reference and unambiguous public metadata. Fallback requires unique meaningful AXIdentifier, compatible mode and agreeing geometry. Uncertain matches are skipped; older unknown layouts need explicit Save once.

Pending restore and fullscreen readback

Reachable saved windows can be restored; unavailable ones remain pending. Experimental fullscreen success requires mode/display readback and does not prove movement of the same Space.

Unverified or unsupported

Acceptance Pending

Fullscreen, Split View and focus

The automatic experimental exit/move/re-entry branch may change focus and Space state. Same-Space continuity, Split View preservation and real application compatibility are not accepted.

Ambiguous windows and missing discovery

Generic accessibility IDs or equal geometry do not establish identity. Ambiguous relaunch matches and inaccessible unseen windows are skipped, with existing placements preserved.

Display UUID changes across different dock ports

Profiles are keyed by exact hardware display UUIDs and point geometry. Plugging the same monitor into a different Thunderbolt controller that assigns a new UUID creates a separate profile.

Build and evaluate deliberately

The manifest declares macOS 14+ and Swift tools 6.0+. This is a source prototype; the full OS, Intel, display and application acceptance matrix remains incomplete.

Before You Run

A prototype, not a signed public release

Local and CI builds use ad-hoc signing for development. Developer ID, notarization and installation on another Mac are not accepted release evidence.

  1. 1. Review the limits: Read the architecture and verification journal before running the prototype on windows you care about.
  2. 2. Build locally: Run the repository test and build scripts. The app bundle is created for the build architecture with a development signature.
  3. 3. Choose when to run: Launching the app may request Accessibility. Later restores can move windows and change fullscreen. No system logging profile is needed.

Local Development

Compile with Swift Package Manager

Clone the repository, run the isolated test suite, and build a development .app and architecture-labelled ZIP. Launch is a separate, deliberate step.

zsh: macOS 14+ / Swift 6 toolchain 
git clone https://github.com/zalexo/WindowHarbor.git
cd WindowHarbor
./scripts/test.sh
./scripts/build-app.sh

Run open dist/WindowHarbor.app only when you are ready to grant Accessibility and evaluate window movement. Local signing does not establish public release readiness.

WindowHarbor --diagnose

Read-only smoke check: prints version, active logical display count and AX trust, then exits before Engine creation. It does not verify restoration.

WindowHarbor --record-topology

Writes public display metadata to two JSONL files capped at 2 MiB each. Identifiers remain; this is not anonymization, a Space inventory or a restore test.
