Transition-safe layout memory

When you unplug or reconnect a monitor, macOS immediately relocates open windows before displays finish settling. WindowHarbor freezes learning on the first display callback so system-induced window scrambling never overwrites your saved profile.

1. Observing

Debounced capture (0.6s) after AX move/resize events and a 20s visibleFrame reconcile.

2. Frozen

Display callback advances a thread-safe epoch and closes the learning gate immediately.

3. Sampling

Waits for 3 consecutive identical usable screen snapshots (1s apart, max 12 attempts).

4. Restoring

Applies saved floating or maximized frames (up to 2 writes with immediate 4 pt readback).

5. Verifying

Delayed 1s readback checks for post-restore drift and quarantines rejected windows.

6. Cooldown

Holds a 5s post-transition cooldown before reopening automatic layout learning.

Exact display environment keys

Each profile is keyed by the sorted display UUIDs and rounded point frames (origin, width, height) of all active non-mirroring screens. Window placements are stored normalized to each display's visibleFrame (accounting for Dock and menu bar) and clamped on restore.

Live session window registry

PIDs, window titles, and CGWindowID are not durable identities. WindowHarbor maintains an in-memory registry binding (PID, process launchDate, CFEqual AXUIElement) to a unique session UUID, matching only unambiguous live elements.

Engineering and privacy invariants

Built as a resident LSUIElement accessory app in pure Swift and AppKit with zero third-party package dependencies.

No Private WindowServer APIs SIP Intact

Zero private WindowServer calls or code injection

WindowHarbor uses public macOS Accessibility (AXUIElement) for geometry, AXFullScreen only as a read-only attribute hint, NSScreen, Core Graphics display reconfiguration callbacks, and NSWorkspace notifications. It never calls private SkyLight/CGS symbols, never injects into other processes, never alters System Integrity Protection, and only registers a Login Item when explicitly toggled in the menu.

100% Local Storage

Strict privacy by omission

WindowHarbor never reads, logs, or persists window titles, document URLs, window contents, or screenshots. There is zero telemetry and zero network code. 

~/Library/Application Support/WindowHarbor/
├── profiles.json         # mode 0600 (atomic write)
├── profiles.json.backup  # previous known-good state
├── trace.log             # 2 MB ring log (no titles/URLs)
└── topology-log.jsonl    # optional display event log
Data Integrity

Non-destructive profile persistence

Before writing a new layout, the existing database is copied to profiles.json.backup and the update is committed atomically inside a 0700 directory. If reading profiles.json fails on launch, WindowHarbor surfaces the error in the menu bar and blocks all writes rather than overwriting your file with an empty database.

Resident-Safe Recovery

Pending Space restore, delayed verification, and single-step Undo

Windows on inactive Mission Control Spaces that are invisible during a monitor settle remain marked as pending for that display setup and are restored when you switch to their Space. A 1-second delayed readback quarantines windows that drift after animation so failed restores are not learned as new positions. Any automatic or manual restore can be reverted with Undo Last Restore without touching profiles.json.

Current scope and explicit non-goals

WindowHarbor is an active engineering prototype. We document exact boundaries between what is implemented and tested in code today versus open macOS platform limitations.

Implemented in current build

Shipped in Code

Ordinary floating and maximized windows

Learns and restores standard Accessibility windows for .regular macOS applications. Maximized means filling the display's visibleFrame, not toggling internal AppKit zoom state.

Transition freeze and quarantine

Blocks learning during display reconfiguration, sleep/wake, and cooldown. Quarantines windows that reject a target frame until you choose Save Current Positions.

Single-step Undo and diagnostic archives

Reverts the last restore in the current epoch from memory, and packages privacy-safe diagnostic logs (trace.log, topology-log.jsonl, summary) into a local zip archive.

Not claimed as solved

Explicit Non-Goals / Open

Native macOS fullscreen Spaces

AXFullScreen is read only as a non-destructive hint so fullscreen windows are skipped during geometry restore. WindowHarbor does not exit fullscreen or move fullscreen Spaces across displays.

Moving windows across Mission Control Spaces

Public macOS APIs do not move windows between Desktop Spaces. WindowHarbor does not reassign windows to different Spaces or manage Split View and Stage Manager layouts.

Cross-relaunch window matching and display aliases

Window identity is bound to the live process session (sessionID). Restarting an app or restarting WindowHarbor requires saving positions for the new session rather than guessing by window title or index. Display UUID changes across different dock ports are not auto-merged.

Installation and quick start

Requires macOS 14.0 (Sonoma) or newer. Choose between downloading the prebuilt release bundle or compiling from source with Swift Package Manager.

Option A · Prebuilt App

Download from GitHub Releases

Fastest way to run WindowHarbor without installing Xcode or command-line build tools.

  1. 1. Download and move to Applications: Grab WindowHarbor-macOS.zip from GitHub Releases, extract WindowHarbor.app, and drag it into /Applications.
  2. 2. Allow in System Settings: Try to open WindowHarbor.app. Because builds use ad-hoc signing without Apple Developer ID notarization, macOS Gatekeeper will pause the first launch. Open System Settings → Privacy & Security, scroll down to Security, and click Open Anyway.
  3. 3. Grant Accessibility permission: Click the WindowHarbor icon in your menu bar (Cmd-drag icons if hidden behind a MacBook notch) and select Grant Accessibility Access...
Open GitHub Releases CLI alternative: xattr -dr com.apple.quarantine /Applications/WindowHarbor.app
Option B · Build from Source

Compile with Swift Package Manager

Clone the repository, run the Swift Testing suite, and package a local release .app bundle with ad-hoc code signing.

zsh · macOS 14+ / Swift 6 toolchain 
git clone https://github.com/zalexo/WindowHarbor.git
cd WindowHarbor
./scripts/test.sh
./scripts/build-app.sh
open dist/WindowHarbor.app

Tip: Set SIGNING_IDENTITY="Developer ID Application: ..." when running ./scripts/build-app.sh if you have a local certificate and want a persistent TCC Accessibility identity across rebuilds.

WindowHarbor --diagnose

Read-only smoke check: prints version, active logical display count, and Accessibility trust status, then exits without registering observers or writing files.

WindowHarbor --record-topology

Runs a standalone display reconfiguration recorder that appends anonymized display geometry events to topology-log.jsonl without moving windows.
